Or: Give the team a job. Keep the steering wheel.

DOCUMENT CLASSIFICATION: Project guide / Garage-built, owner-operated

DATE RECORDED: October 19, 2026

UPDATED: October 20, 2026 — RATBAG branding and home-screen images

LOCATION: Floyd Labs, somewhere between the workbench and the coffee pot

BEVERAGE: Coffee that tastes like motor oil. Instructions that do not.

CURRENT STATE: Application verified locally; installation awaiting a connection

RATBAG turns a coding request into a saved plan, proposed changes, automated checks, and a separate review. You choose the project and the result. The app coordinates the models and keeps the work available for inspection.

The browser is the control panel. The the server does the work, so you can follow a task from your phone, iPad, or desktop. Your original project files stay unchanged while RATBAG prepares a downloadable change file called a patch.

Built in the garage. Ready for your work.

Open it (Or: The useful part comes first)

Once the operator has completed the Installation, use RATBAG on the server. Your device needs access to the same private network as the server. If the server opens but the app does not, use the connection recovery guide.

  1. Open Help → Run guided setup, or follow the first-visit setup card.
  2. Select an existing project, or choose Create practice project for a safe first run.
  3. Add the GLM, DeepSeek, and MiniMax account keys if they are not already supplied by the server. One GLM entry supplies both GLM roles.
  4. Select Check connections. The walkthrough saves entered keys first, then makes small real requests to verify the four core roles.
  5. Keep Smart model routing, then choose Create first task.
  6. Choose the project, describe one change, keep its recommended checks, and select Start task.
  7. Follow the task. At Ready for review, open the evidence and select Download patch.

Creating the practice project, choosing a theme, and selecting a routing preset do not call a model. Connection checks and running a task can use provider credits. RATBAG does not merge, push, or publish your changes.

What is in the workbench (Or: Meet the crew)

RoleWork it performs
ArchitectReviews the plan, helps with repeated failure, and reviews the final candidate. A rejection prevents advancement.
BuilderReads selected source files, writes the plan, proposes the changes, and repairs unsuccessful attempts within the run limits.
Find filesFinds project files relevant to the request.
Find referencesFinds matching code and where it is used.
Tests & reviewRuns the chosen checks in a separate working copy and reviews the proposed changes.
RoutingUses declared project checks and an explicit model arrangement. Decisions have recorded reasons.

Smart applies the original four-model arrangement below. Manual keeps your saved role choices. Saving a core role in Advanced selects Manual automatically; you can explicitly select Smart again to restore the preset. Smart is a transparent preset, not a claim that the app has measured every possible model or found the cheapest one. It does not silently swap providers when a request fails.

Both native GLM roles are pinned to https://api.z.ai/api/coding/paas/v4. DeepSeek uses https://api.deepseek.com/v1; MiniMax uses https://api.minimax.io/v1. The optional Router model connection uses OpenRouter. Keep it disabled unless you have a working account for it. The ordinary deterministic routing layer still works without that optional connection.

Make it yours (Or: Bella has opinions about screen space)

Open View and choose System, Dark, Light, or High contrast. Choose Automatic, iPhone, iPad, Desktop, Widescreen, or Ultrawide for the workspace layout.

RATBAG's mascot keeps its safety-orange waist pack in every theme. The background, surrounding lettering, and contrast adapt to your selection. Same garage foreman, different lighting.

On desktop, he heads the project rail. On iPad, he shares a shelf with your projects. On the phone, he appears beside the RATBAG name in Work and takes the larger header in More. The controls stay in their usual places.

The layout profiles change how work, team, review, and activity are arranged. The phone has focused views and bottom navigation; larger displays keep more of the work visible together. Use Automatic for everyday use, or choose a profile yourself. Theme and layout are remembered by that browser. They do not change a running task or spend provider credits.

Install it yourself (Or: For the person maintaining the server)

Ordinary users can stay in the browser. This section is for the person running the service.

For the server, use the installation guide. Its one-command installer retains earlier releases, keeps saved work separately, and checks the local service before reporting it running. The guide includes the additional route check needed at the real server address.

Requires Python 3.11 or later and Git. RATBAG itself has no third-party Python or JavaScript application dependencies. A chosen project still needs its own installed test tools and libraries.

From the application folder, run:

python3 -m swarm

Then open http://127.0.0.1:8765 on that same computer. That address is for a local installation; remote devices should use the server address above.

For a server reached from other devices, configure an access key and the allowed hostname before starting it. Use an environment or secret manager already maintained by the operator for secret values. Do not put secrets into a URL or source file.

SettingPurpose
SWARM_ACCESS_TOKENPrivate key for access to this RATBAG service when listening remotely. This is separate from a model provider key.
SWARM_ALLOWED_HOSTSAllowed hostnames or IP addresses, separated by commas, without a scheme or port.
SWARM_BASE_PATHPath used by a server installation, such as /swarm.
SWARM_PROJECT_ROOTSFolders the project picker should search; use the host operating system's path separator.
SWARM_DATA_DIRPersistent folder for saved settings, history, evidence, and separate workspaces. Defaults to .swarm-data.
SWARM_HOST / SWARM_PORTListening address and port; command-line --host and --port can override them.
GLM_API_KEYKey for both native GLM roles.
DEEPSEEK_API_KEYKey for the Builder.
MINIMAX_API_KEYKey for the scouts.
ROUTER_API_KEYKey for the optional OpenRouter connection; enabling that connection is a separate choice.

With the service settings already supplied, a remote listener can start with:

python3 -m swarm --host 0.0.0.0 --port 8765

The service refuses remote listening without an access key. Route the chosen the server path to this service through the hosting web server. Use the deployment instructions included with the installed release for that host's actual paths and service names; do not replace existing the server routes.

Keys and restarts

Account keys typed into the app stay in the running server's memory. They are not saved in browser storage or the settings file. A server restart clears those typed keys. Supply keys through the service environment if the installation should recover without asking the owner to enter them again. Non-secret settings, project selections, and run evidence are separate from credentials.

The browser access key is also held only in the open page's memory. A reload can ask for it again. Opening help in its separate page leaves the app tab available.

Projects and saved work

The picker lists Git projects already present in the server's configured folders. It does not clone a remote repository or upload a project from the phone. Create practice project creates a small real example on the server for onboarding.

Use projects you trust. RATBAG checks changes in separate Git working copies, but repository tests still execute as code on the server. Test processes receive a reduced environment without model keys. This release does not supply a container or virtual machine around each run.

Keep the data folder on persistent storage and include it in the operator's backup routine. Failed attempts, patches, and review evidence are retained. The app has no automatic destructive cleanup. For a consistent backup, pause the work, stop the service normally, copy the complete data folder, and then restart it. Keep any service secrets in their existing private backup process.

Verify the installation (Or: Bowser wants receipts)

Run the application checks from its source folder:

python3 -m unittest discover -s tests -v

The suite uses temporary Git projects and local test servers. It does not spend provider credit. A model account check is a separate explicit action in the app; it verifies the chosen connection, not the quality of all future coding results.

Then verify the actual installed address from a second device: open RATBAG, finish guided setup, create a practice task, open its evidence, and download the result. Use the QuickStart for the exact flow. The delivery-specific results are in Verification.

The behavior described here is implemented in swarm/server.py, swarm/engine.py, swarm/gitops.py, swarm/providers.py, and the files under web/. The original guide is retained at README v0.1.
